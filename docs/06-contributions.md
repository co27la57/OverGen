# 06 · 贡献清单与定位

## 先划边界：现有工作已做到哪
- **DSAGEN（ISCA'20）**：自动合成可编程空间加速器；编译器达手调 **89%** 性能；DSE 平均 **1.3× perf²/mm²**。验证主要靠 gem5 + RTL 仿真。
- **OverGen（MICRO'22）**：FPGA overlay 生成，**已 "Verified on FPGA"**；编译/重配置时间少 **~10000×**；对比对象是 DSE-HLS 框架 AutoDSE。
- 结论：**"移植上 FPGA"本身不新**，新意必须在留白里找。

---

## 贡献清单

### C1 ★ 真实硅上「可编程 overlay vs HLS 固定加速器」同板同 kernel 实测对照（含功耗）
- **相对谁新**：DSAGEN/OverGen 的 PPA 多为建模/仿真，或与 AutoDSE 的框架级对比。
- **为什么新**：把"可编程性的代价"量化成**真实测量的 power/energy**，同 kernel、同 7020、同工具链的受控对照极少见。
- **证据**：7020 上两组实现的 LUT/DSP/BRAM、时延、**实测功耗/能耗**。

### C2 资源受限器件上的可编程 overlay 可行性与效率边界
- **相对谁新**：原工作面向较大器件；"最小可用 overlay 有多大、何时崩"未被系统刻画。
- **为什么新**：刻画 commodity Zynq 上的 **feasibility/efficiency frontier**，产出设计准则。
- **证据**：不同 fabric 规模 vs 性能/资源曲线族。

### C3 ★ 面向 ARM SoC 的真实集成方案（ARM PS host + PL overlay）
- **相对谁新**：DSAGEN 假设 **RISC-V host + gem5**；OverGen 不聚焦 ARM 集成细节。
- **为什么新**：可复用的 **SoC 集成 recipe + 轻量 runtime/driver**（AXI 派发、内存一致性、kernel launch），降低复现门槛。
- **证据**：开源设计 + 运行时 + 部署流程。

### C4 真实重配置/时分复用成本实证（校验 ~10000× 主张）
- **相对谁新**：10000× 是框架主张；真实 bitstream 切换/部分重配置代价未在低成本板上系统验证。
- **证据**：kernel 切换延迟实测曲线（正/负结果都有价值）。

### C5 工具链轻量化与可复现性（开源贡献）
- **相对谁新**：dsa-framework 依赖重（Docker + Chisel + gem5 + LLVM），门槛极高。
- **证据**：精简仓库 + 教程 + 端到端复现脚本，对接标准 Vivado 流程。

### C6（进阶）新负载域 / 新原语的泛化验证
- 接未覆盖域（**LLM/VLM、FHE** —— 正是 Jian Weng 当前方向），或在 ADG DSL 加新原语。

## 诚实标注：这些**不算**贡献（别写进贡献列表）
- ❌ 单纯把 dsa-framework 跑通（**复现/学习**）。
- ❌ 单纯"把生成的加速器上 7020"（OverGen 已 FPGA verified，属**工程移植**）。
- ❌ 只改 pragma 看仿真差异（教程例子的**重量级复述**）。

> 关键：把复现与工程移植当作**手段**，用 C1/C4 这类**实测结果**抬升为 "measurement/empirical study"。

## 预判审稿人质疑 & 回应
1. **"OverGen 已上 FPGA 了"** → 贡献不是"首次上板"，而是**受控对照 + 实测功耗 + 低成本边界**。
2. **"7020 太小，没代表性"** → 恰恰是 scaling 研究对象；作为平民级器件，可复现性反而更强。
3. **"这就是工程复现"** → 用 C1/C4 实测数据定义为**实证测量研究**，并提供 C3 可复用集成方案。
